# 接口契约（2026-10-22 实测，2026-11-03 整理）

- 同源前缀：`https://echotik.live`
- 方法：**仅 GET**
- 鉴权：复用**已登录浏览器的页面会话**（`Authorization`、`X-User-Id` 等头由页面自己带）。
  这些值不导出、不打印、不落盘。
- 请求上下文还需：`x-region: MX`、`x-currency: MXN`（US → `USD`）
- 只允许这两个路径（SDK 白名单写死，传别的会被拒）

---

## 1. 商品销量榜

```
GET /api/v1/data/products/leaderboard/top-sold
```

### 参数（query）

| 参数 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `time_type` | 是 | `daily` / `weekly` / `monthly` | 周期类型 |
| `time_range` | 是 | daily：`20261021`<br>weekly/monthly：`20261012-20261018` | 日期格式固定 `YYYYMMDD` |
| `product_categories[]` | 是 | 类目 ID，**重复传** | 必须给**完整路径**，见第 3 节 |
| `order` | 是 | `sale_cnt` | 按销量排序 |
| `page` | 否 | 1.. | 默认 1 |
| `per_page` | 否 | 1..20 | 默认 20（上限 20） |

> 用 `product_categories[]=824328&product_categories[]=839944&product_categories[]=601226`
> 这种**重复键**形式，不要用逗号拼成一个值。

### 返回

```json
{
  "code": 0,
  "msg": "...",
  "data": [ /* 每行一个商品 */ ],
  "meta": { "current_page": 1, "per_page": 20, "total": 1000, "last_page": 50, "from": 1, "to": 20 }
}
```

`data[]` 字段（实测 16 个）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `product_id` | string（19 位） | **必须按字符串处理**，转数字会精度丢失 |
| `product_name` | string | 原始标题（含营销词，别直接抄） |
| `category` | string | 主类目名 |
| `categories` | string[] | 类目链 |
| `region` | string | `MX` / `US` |
| `avg_price` / `min_price` / `max_price` | string | **展示值**，形如 `MX$84.86`，不是纯数字 |
| `sale_cnt` | string | **选定周期**内销量，**展示值**：`"3645"` 或 `"1.18万"` |
| `total_sale_cnt` | string | 累计销量，同样是展示值（`"2.27万"`），历史可能被数据方修订 |
| `total_gmv_amt` | string | 累计 GMV，带币种与万：`"MX$217.89万"` |
| `influencers_count` | number | 带货达人数 |
| `total_video_cnt` / `total_live_cnt` | number | 视频数 / 直播数 |
| `product_rating` | number | 评分 |
| `review_count` | number | 评价数 |

### 四个必须注意的口径

1. **`sale_cnt` ≠ `total_sale_cnt`**：前者是周期内，后者是累计，混用会把结论算错。
2. **数值字段是展示字符串，不是数字**。实测：
   ```json
   { "sale_cnt": "1.18万", "total_sale_cnt": "8.41万", "total_gmv_amt": "MX$217.89万" }
   ```
   直接 `Number("1.18万")` → `NaN`；`Number("3645")` 能过，所以这个坑是**间歇性**出现的。
3. **价格带币种前缀**：`"MX$84.86"`，同样不能直接转数字。
4. **"万"是展示取整**：`1.18万` 不代表精确 11800 单，做对比时保留原字符串。

### 统一解析函数（包内已提供）

`client.mjs` 导出 `parseMetric`：

```js
import { parseMetric } from "./client.mjs";
parseMetric("3645")        // 3645
parseMetric("1.18万")      // 11800
parseMetric("MX$217.89万") // 2178900
parseMetric("abc")         // null（解析不了就返回 null，绝不返回 0 假装成功）
```

`check.mjs` 对 `samples/` 里每一行都会跑这个函数，解析不了即判失败。

## 2. 类目元数据

```
GET /api/v1/data/products/product-category
```

无 query 参数。返回：

```json
{
  "code": 0,
  "categories": [
    { "id": "824328", "label": "男装与男士内衣", "slug": "menswear-underwear", "parents": [] },
    { "id": "839944", "label": "男士上装", "slug": "mens-tops", "parents": ["男装与男士内衣"] },
    { "id": "601226", "label": "男士T恤", "slug": "mens-t-shirts", "parents": ["男装与男士内衣", "男士上装"] }
  ]
}
```

### 关键坑：三级类目必须给全路径

只传叶子 `601226` 会得到**零行**响应——那不是"市场为 0"，是参数不全。
正确：`824328,839944,601226`（墨西哥男士T恤）。

## 4. 已验证的日期窗口

| 周期 | 示例 |
|---|---|
| daily | `20261021` |
| weekly | `20261012-20261018` |
| monthly | `20260901-20260930` |

不同窗口的数值不能直接互比（周期长度不同）；同 ID 三窗口对照才是正确用法。

## 5. 业务错误与停止条件

| 情况 | 处理 |
|---|---|
| HTTP 401 / 403 | 会话失效，**停下**，由本人重新登录 |
| HTTP 429 | 触发限流，**停下**，不要立即重试 |
| 出现验证码 / 会员墙 | **停下**，交回本人 |
| 业务 `code != 0` | 视为失败，不要把空 `data` 当成"没有数据" |
| HTTP 200 但 `data` 为空 | 先怀疑参数（尤其类目路径不完整），再怀疑市场 |

**HTTP 200 不等于成功**，必须同时校验 `code`、`region`、周期、类目。
