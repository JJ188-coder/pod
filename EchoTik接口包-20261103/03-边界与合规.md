# 边界与合规

本包的能力范围，和你可能踩的红线，都写在这。

---

## 1. 鉴权：只用你自己的会话

| 做 | 不做 |
|---|---|
| 复用**你自己浏览器**里已登录的 echotik.live 页面会话 | 不导出、不保存 Cookie / Token / 会话头 |
| 在页面内发同源请求（页面自己带的头） | 不在站外重放会话、不做跨设备搬运 |
| 显式头模式要求**你自己**提供，运行时读环境变量 | 不把凭据写进代码、日志、样本、git |

样本文件已逐字段扫过（`Authorization`/`cookie`/`token`/`user-id` 类键、40+ 位随机串），
结果为**无凭据**；`samples/` 里只有业务数据。

---

## 2. 额度：会员额度不等于无限调用

- 你买的是标准版会员，接口调用受会员额度约束。
- **每日会员额度如何折算成分页/请求数，尚未独立验证**。
- 因此本包把预算写死：单次运行 ≤5 个新请求、间隔 ≥1.5s、不重试、不轮询。
- 需要更多数据 → 分多次运行，别在一个进程里打满。

---

## 3. 停止条件（遇到就停，不要硬闯）

| 信号 | 动作 |
|---|---|
| 401 / 403 | 会话失效 → 停下，由本人重新登录 |
| 429 | 限流 → 停下，不立即重试 |
| 验证码 / 滑块 | 停下，交回本人 |
| 会员墙 / 付费提示 | 停下，不绕过 |
| 业务 `code != 0` | 当作失败，不重试同一请求 |

**不允许**：短信/邮件轰炸式重试、多账号轮换、代理池切换、伪造区域/币种去解锁别的市场数据。

---

## 4. 数据使用的边界

- 榜单数据是**第三方估算**，不是平台官方成交数据；写进报告要标来源与周期。
- `total_sale_cnt`、GMV 等历史值可能被数据方修订，不要硬编码成长期成立的结论。
- 商品标题、图片**属于原卖家**：可以临摹摄影语言与版式比例，
  不能直接复制其图片、标题、品牌或宣称。
- 不要拿本包做批量抓取建库再对外分发——那是另一套授权问题。

---

## 5. 本包明确不做的

- 不做登录自动化（不存密码、不模拟登录流程）
- 不做多账号管理
- 不做反爬对抗（不伪造指纹、不绕验证码）
- 不碰 EchoTik 之外的平台接口
- 不提供"猜接口"能力：只允许白名单里的两个只读路径

---

## 6. 出了问题的正确顺序

1. 先 `node check.mjs`，确认是**契约/数据格式**问题还是**会话/额度**问题。
2. 会话类（401/403/验证码）→ 本人重新登录，不做脚本补救。
3. 额度类（429）→ 隔一段时间再跑，且降低请求数。
4. 业务类（code != 0 或 data 空）→ 先查参数（尤其类目是否给了三级全路径）。
5. 以上都不是 → 对照 `依据/2026-10-22_网页接口-EchoTik-report.md` 的原始观测记录。
