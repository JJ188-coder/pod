# 生图工作室 0.3：稳定恢复与商品保真

本版保留原 `skills/magpie-image/SKILL.md` 原文，修复执行器，新增 `product-fidelity` 技能。原技能中的同步请求、限流后降并发重跑等旧说明，不应覆盖新执行器的恢复规则。

## 商品图的默认路线

1. 加载原 `magpie-image` 和新增 `product-fidelity`；商品素材也加载原 `pod-pipeline`。
2. 明确本款、颜色、适用型号与事实来源；以真实商品照片为商品参考，定稿图案、人物和场景分别传入，不互相替代。
3. 由 `product-fidelity.mjs compile` 输出已绑定参考图的任务清单，再使用 `batch-images.mjs --provider image2`。编译默认只输出JSON，不生成、不联网。
4. 先预检；有本批明确生成授权才加 `--run`。同一清单恢复，不新建ID、不跨通道补发。
5. 生成结束只代表文件已保存。使用 `review-pending` 对照原图逐项检查，再记录实际验收；保真未核实前不用于新上架。

商品轮廓、款式、颜色、结构/孔位、材质观感、印花内容与比例是锁定项。缺商品实拍不能只把图案文件标为商品参考。多型号商品不把某一机型的孔位图当所有型号的准确展示。不明事实保持缺失，不默认填写 iPhone 15 Pro/18 Pro Max。

精确文字/印花能在已确认的平面区域确定性合成时优先用原稿；现有服装平铺模板不适用于任意手机壳、姿势或褶皱。图生图和提示词都不能保证像素级保真，SHA只能证明使用了同一文件，不能证明与实物完全一致。事实描述与来源文件仍须实际对照；清单哈希不是签名，也不能证明该文件必定由编译器产生。

## 恢复规则

- 提交前保存本地请求；成功取得上游任务ID后立即记录，随后只查询该ID。
- 超时、断线、5xx、无有效任务ID等结果不明，不自动再POST，也不自动切换供应商。
- 401/403/429或额度错误阻止剩余新提交；已提交任务保留。解除后先核原任务，不靠换ID规避限制。
- 已生成原图下载/复制失败，只补下载/复制。目标位置的旧图片必须与本任务记录SHA一致才可复用。
- 旧版本遗留且无法核清是否提交的任务保守阻塞，不自动重建。上次误测试生成的文件和记录不迁移、不删除、不续跑。
- 单图未完成时保留返回的 `request_id/task_id`，调用新版 `image2_result`，或本地 `python3 -I -B scripts/image2_mcp.py result --request-id 原ID`。批次用原清单续跑，不重编译成新任务。
- 多任务续查中，只有确实在进行或待补保存的任务才记 `pending`；全部已失败/冲突/被阻断时记 `partial_failure`，不要无休止轮询。
- 新一版/明确重新生成使用新的请求ID或variant，这是一笔新的生成，不等同于恢复。
