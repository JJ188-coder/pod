# MiniMax H3 视频生成

## 这个技能解决什么

用户只要描述想拍的视频，不要让用户手写 JSON、轮询接口或管理任务文件。商品素材包还应加载`pod-pipeline`的`references/product-media-standard.md`，适用于所有品类，不只卫衣/T恤。你负责：

1. 把需求整理成适合 minimax-h3 的完整提示词；
2. 用 MCP 工具登记批次（此时**不花钱、不提交**）；
3. 只启动一次后台执行器，由它提交、轮询并下载；
4. 后台结束后交付本地视频链接和失败原因。

## 先检查环境

实际生成前，每个会话第一次使用调用 `video_check`；同一会话已经通过就不要重复调用。只写提示词或维护本技能时跳过环境检查、批次登记与生成，不因加载技能触发执行流程。

- `ready: true`：直接开始规划。
- `credentials.configured: false`：告诉用户运行下面命令，等他完成后继续：
  ```
  node <cli_path> setup
  ```
  `<cli_path>` 用 `video_check` 返回的 `cli_path`。也可以让用户设置 `MINIMAX_VIDEO_API_KEY` 后重试。
- `ok: false`：把 `checks` 里失败的项直接告诉用户，不要绕过。

不要索要或回显 API Key。用户如果已在聊天里贴过密钥，提醒他轮换，并改用本机隐藏输入配置。

## 先判断需求

| 用户说法 | 做法 |
|---|---|
| 一条几秒的视频、广告片、产品展示 | 单条任务 |
| 同一主体做多个版本，或多款商品各一条 | 一次准备本批全部任务，无固定本地批次数量上限，一次后台全量并发提交；不逐条等受理或完成 |
| 给一张/多张图加动作 | `images` 传参考图，提示词写明保持外观一致 |
| 用户明确提供参考音频 | `audios`最多3段；说明用途但不承诺精确复刻。商品包默认省略，不能自行制作本地TTS参考 |
| 需要精确字幕、价格、品牌文字 | 视频模型不擅长画字，建议后期叠加 |
| 用户只要方案、不要求生成 | 只给提示词和参数，不登记批次 |

## 参数规则

| 参数 | 规则 |
|---|---|
| `aspect_ratio` | `portrait`/`9:16` 竖屏，`landscape`/`16:9` 横屏；不支持 1:1 |
| `resolution` | `480p`、`768p`、`1080p`；没有 720p |
| `duration` | 整数 1–15 秒；**1080p 最多 10 秒** |
| `images` | 最多 9 张；HTTPS URL、本地绝对路径或 data URL |
| `audios` | 最多 3 段；同上 |
| `seed` | 可选，0–2147483647；相同 seed 不保证逐帧一致 |
| `prompt_skill` | 默认 `true`；你已经写好完整提示词时传 `false`，避免服务端再次改写 |
| 每批数量 | 至少1条，无固定本地数量上限；仅执行本批已授权数量 |

服装商品视频默认：每款1条、严格9:16、768p、15秒、`prompt_skill: false`，使用下方通用口播模板；其他商品包保留10秒，普通非商品视频保留6秒。用户明确指定的时长、语言和已确认批次规格优先；新默认不追改运行中或已登记任务。1080p最多10秒，遇到“15秒＋1080p”先说明冲突并确认取舍，不静默缩时或降清晰度。1080p按费用规则确认，不自动升档；不能改会话或供应商模型设置。


## 手机壳类商品的结构保真（2026-11-10）

手机壳的镜头模组是明显高出背板的凸起平台，边缘有阶梯落差。视频提示词必须写明：

- `保持镜头模组为高出背板的凸起平台，边缘有阶梯落差和阴影；印刷面低于镜头平台`
- 禁止把镜头区生成成齐平或凹陷的平板

首帧图先按这个结构验收（镜头平台必须比背板高一档），首帧合格再生成视频；不要用不合格的首帧直接跑视频。

**正反面同样必须验收**：手机壳从外侧打印，图案在外表面。首帧不得是空壳内腔（镜头孔成内凹井、图案贴在内衬）。要求手机已装进壳里、背面朝镜头、图案正读、内腔完全不可见。出现内腔视角的首帧直接弃用，不烧视频额度。

手机壳类商品要求「手机已装进壳里、背面朝外、图案正读、内腔不可见」，禁止空壳内腔视角。

## 写提示词

6 秒视频只安排**一个主要动作**。不要塞多场景、多人对白和复杂转场。

按这个顺序写，缺的项可以省略：

1. **风格**：电影级写实 / 产品广告 / 动画 / 纪录片手持
2. **主体**：人物或产品，外观、服装、材质、颜色
3. **场景**：地点、时间、天气、背景元素
4. **动作**：一个连续动作，写清起点和终点
5. **镜头**：景别、机位、运镜（缓慢推进、环绕、固定、跟随）
6. **光线与质感**：方向、软硬、反射、景深、运动模糊
7. **声音**：环境声、动作声、对白（如需要）
8. **一致性与限制**：保持参考图外观一致；不要变形、多余手指、文字、水印、Logo、闪烁、跳变

商品视频默认由画面中的人物开口讲解，声音由视频大模型原生生成：**不运行`say`/本地TTS，不另做配音文件，不默认传`audios`，不事后替换声音掩盖口型问题。** 提示词写出准确的短对白，要求说话时嘴部清楚可见、声音与嘴形匹配；不能用环境声、画外旁白或随机张嘴代替。默认墨西哥西班牙语，用户明确的目标语言优先。非服装可由人物持物/使用并介绍，不硬套上身展示；只有用户明确要无对白或纯产品片时才不安排人物口播。

### 通用服装口播模板（默认15秒）

适用于T恤、衬衫、卫衣、外套、裤装、裙装、连衣裙及套装。固定的是展示结构，不是每款都念同一段话；不是走秀、图片轮播或与商品无关的脸部宣传片。

**先完成本款适配，再调用生成工具：**

1. 从本款参考图与已确认资料锁定款式、颜色、图案和一个主要可见特点，必要时补一个次要特点。没有明确细节就展示整体轮廓，不猜面料成分、弹力、保暖、防水、舒适度、显瘦效果、价格、折扣或销量。参考图中的文字按需用已有OCR核实；不能把生成画面当商品事实。
2. 先写定2—3句口播：商品相关的开场 → 一个真实特点 → 一个查看详情/尺码的引导。15秒墨西哥西语建议总计25—32词，开场约4—6词，保留停顿和完整尾音；这是规划范围，不是模型时长保证。中文约40—55字，其他语言按自然语速估算。没有已确认的商品链接，不说“点击下方链接”“已挂购物车”；不使用无依据的第一人称使用经历、虚假稀缺或效果保证。
3. 给每句台词配一个能看见的展示动作：讲印花时示意图案但不遮挡，讲剪裁时调整站姿或小幅侧身，讲长度时保留对应的完整轮廓。全片选1—2个自然动作，不反复指衣服、不拉扯面料暗示弹力。只掌握正面参考时不安排转背或内里特写。
4. 按品类选构图：上装用嘴部到衣摆均可见的中景；裤装、裙装让嘴部到裤脚/裙摆完整入画；连衣裙和套装保留全身与各件比例。口播时嘴部保持可辨，商品不因露脸被裁掉；细节特写只放在短暂停顿中。
5. 把下面所有方括号替换为本款事实、确定的动作和准确台词，删除未用镜头；`prompt`里只提交最终拍摄指令，不包含备选台词、商品分析或“请自行编台词”。`duration`与分镜一致，`prompt_skill: false`，默认省略`audios`。

**15秒成片提示词骨架：**

```text
写实真人穿搭分享风格，15秒，严格9:16竖屏。同一位适合本款受众的成年模特穿着参考图中的[本款服装及颜色]，在[一个简洁生活化场景]中面对镜头，边开口介绍边展示衣服。商品是视觉主角，人物、手势与镜头都为展示商品服务。

0—3秒：第一帧直接出现穿着商品的清晰画面，用[兼顾嘴部与本款商品的景别]构图。模特自然看镜头，准确说：“[开场短句]”，同时[一个引导注意商品的小动作]。没有片头、自我介绍、空镜或缓慢入场。
3—11秒：准确说：“[一句关于本款真实可见特点的短句]”，同步[能展示该特点的自然动作]，让观众看清[本款展示重点]。讲话时保留嘴部清楚可见；如确有必要，只在说话停顿中短暂切到该细节，再回到人物，不让口播变成画外旁白。
11—15秒：回到最能展示本款轮廓的正面角度，看镜头准确说：“[一句自然的详情或尺码引导]”。约14秒前说完，最后约1秒保持自然姿态和清晰商品画面，尾音完整，不突然切黑。

由视频大模型原生生成自然的[目标语言及口音]人物声音及同步的嘴唇、下颌说话动作。必须是画面中这位模特本人说话，不是旁白；台词与动作语义一致，表情和眼神自然。全片保持同一声线，自然语速，有轻微停顿，不抢读、不额外加台词。人声清晰居前，只保留轻微环境声，不添加配乐。

以一个稳定连续主镜头为主，最多补充1—2个必要镜头，正常速度，不用密集快切、炫技转场、旋转运镜或全程慢动作。柔和有层次的光线，背景与服装适当区分，准确呈现商品颜色和轮廓。手势不挡图案和关键细节，模特不过度摆拍。

保持同一人物、同一衣服、同一颜色与场景。严格保持参考图中的版型、长度、图案、文字、装饰位置和比例；不改变或新增商品结构，不展示参考图未支持的背面或内里。不要衣服变形、印花漂移、面部跳变、多余手指或叠化分身。不要生成字幕、水印、促销贴纸或新增Logo。
```

**台词示例（不是每款通用事实）：** 已确认“黑色上装、正面有印花”时，可用25词：

> “Mira el estampado de frente. Este diseño destaca sobre el negro; te lo muestro de cerca para que lo veas. Revisa los detalles y tallas.”

对应动作是用手在图案旁示意、不遮挡，停顿时给短近景，再回到正面说结尾。若该款没有印花，不能沿用这句；可用“Fíjate en cómo queda.”开场，再讲本款真实轮廓。不要把示例自动当成所有商品的卖点。

**其他时长：**

- 明确10秒：压成“0—2秒开场、2—7秒一个特点与动作、7—10秒简短引导”，西语约18—22词，末尾留0.5—1秒；不足就删次要内容，不加速念稿。
- 明确6秒或更短：只保留一个动作和一句短话，合并开场与特点；太短放不下有效口播时先确认更长时长或无对白，不无声交付冒充口播。
- 其他时长按约20%开场、55%展示、25%收尾重排，不能只改`duration`却留着15秒分镜。用户已给台词时先估算能否自然说完；超时给精简建议或延长选项，不擅自改必须逐字保留的内容。

其他商品包仍可用10秒简版（先替换占位符）：

> 写实产品短片，严格9:16。人物展示参考图中的[本款产品]，开头直接展示使用效果，中间一个连续自然展示动作，最后看镜头引导查看商品。由模型直接生成自然墨西哥西班牙语人物声音，与人物口型同步；说话时嘴部可见，语速自然。准确说两句：[一句已确认的产品特征]。“Mira los detalles en el producto.” 保持产品颜色、图案、文字和结构一致，不变形、不叠化分身、不多说无关内容、不生成字幕/水印/新Logo，不添加配乐。

图生视频时明确写：

> 保持参考图中的人物面部、发型、服装和体型一致；只改变动作和镜头，不改变身份特征。

不要承诺：

- 仅凭提示词或参考音频就保证每句对白严格口型同步；这是验收要求，不是生成接口保证；
- 多张参考图自动对应到指定镜头；
- 相同 seed 完全可复现；
- 视频里能稳定生成精确文字。

## 执行流程

### 1. 规划并确认一次

把用户需求整理成本批全部任务，不人为拆成每批10条。服装商品先按通用模板填好准确台词、对应动作和本款事实；确认没有未替换占位符、时长冲突或未经证实卖点。下面以15秒服装口播为例，`prompt`填写最终完整拍摄指令，再调用 `video_prepare_batch`：

```json
{
  "client_request_id": "mm-20261103-141500-a1b2",
  "jobs": [
    {
      "prompt": "完整提示词……",
      "aspect_ratio": "portrait",
      "resolution": "768p",
      "duration": 15,
      "images": ["/absolute/path/product.png"],
      "prompt_skill": false,
      "output_name": "product-hero"
    }
  ]
}
```

`client_request_id` 用 `mm-日期-时间-4位随机`。如果工具调用超时后重试，**复用同一个 ID**，这样不会重复登记。

返回 `submitted_to_provider: false` 表示本次登记没有调用生成；若`deduped:true`，原批次可能已提交，必须按返回的实际状态处理。

当前会话若仍缓存旧MCP的10条schema，不拆批绕限制、不重启活跃服务。代理将同样字段的整批JSON保存到本地，用已安装插件的CLI登记（不让用户手填）：

```bash
node <plugin-root>/dist/cli.js prepare --file /absolute/video-batch.json
```

复用返回的批次ID和`run_command`，CLI只是登记入口，仍须遵守下一步费用授权。文件更新不代表活跃MCP热加载；新MCP进程才加载新schema。

### 2. 付费确认

用户明确要求生成时，常规情况直接进入下一步。以下情况先用一句话确认，得到同意再运行：

- 单批超过 4 条；
- 使用 1080p；
- 用户没有明确说“现在就生成”，只是在讨论方案。

确认时说清：条数、分辨率、时长，以及“文档没有提供单价和取消接口，提交后可能计费且无法取消”。不要编造价格。取消本地固定数量上限不是无限费用授权；已明确确认的同一批不重复询问，超出该批数量、规格或新增收费重做另核授权。

### 3. 只启动一次后台执行

使用 `video_prepare_batch` 返回的 `run_command`，调用**一次** Bash：

```
run_in_background: true
```

要求：

- 不要加 `&`，不要用前台运行；
- 不要循环调用 `video_status`；
- 不要重复调用 `video_prepare_batch`；
- 不要自己发 HTTP 请求；
- 一个批次只允许一个执行器。
- 默认本批全量并发提交，每条独立请求，不等上一条受理或生成完成；这不保证供应商同时渲染。按需显式加`--concurrency N`或设置`MINIMAX_VIDEO_CONCURRENCY`主动降低并发，必须正整数，不再硬限4或10。
- 显式N统计同一账本所有批次在途任务；但没有限流参数的其他执行器不受N约束，不把它当账户级限速器，也不靠拆批规避上游限制。查询并发4、下载并发2，独立于生成提交。
- 遇认证/额度/401/402/403/429暂停未派发请求与后续查询，已发出的不能撤回。全量提交可能在首个错误回来前已经全部发出，不能保证因此免计费。

后台命令会提交、轮询、下载，结束后宿主会通知你。等待通知期间，如果用户主动问进度，可以调用一次 `video_status`（不要 refresh 也可以），但不要每隔几秒查。

### 4. 给一次进度页链接

后台任务启动后，调用一次 `video_open_progress`：

```json
{ "batch_id": "b-xxxx" }
```

把返回的 `url` 用 Markdown 链接交给用户，并说明：

- 页面只读，每 2 秒读取本机记录，不额外查询供应商；
- 关闭页面或监控进程不影响生成；
- 百分比来自接口记录，排队与渲染无法单独区分；
- 链接含本机访问令牌，不要外传。

同一批次重复调用会返回同一个链接。用户问进度时先让用户看页面，不要为刷新页面反复调用工具。

### 5. 后台结束后交付

收到完成通知后：

1. 调用 `video_status` 读取最终状态（此时不需要 `refresh: true`）；
2. 商品视频先完成下面的实际验收，再按下方格式交付；已下载但未验收的标待复核，不叫合格成片；
3. 如果 `exit_reason` 是 `pending` 或 `partial`，说明还剩什么，并给出一条恢复命令，**不要自动再开一个后台任务**。

## 商品视频实际验收

- 用`ffprobe`读取实际视频流宽高、SAR、旋转、时长和音轨。最终显示宽×16=高×9、SAR=1:1；仅提交`portrait`不算验证。1056×1920不是9:16；保持比例缩放/补边到9:16，保留母版，不拉伸、不盲裁商品。交付报实际像素，不把名义1080p写成1080×1920。
- 连续音画检查说话内容、清晰度、逐音节口型、首尾和商品一致性。静帧张嘴、音轨存在、声音波形相关都不能证明口型同步；ASR是辅助，转写与脚本差异未排除时不能说一致。
- 服装模板另核：开头约2秒内商品与人物开口已出现；所讲特点确实有对应展示、动作不遮商品；构图覆盖该品类关键轮廓；没有乱加卖点、画外旁白替代、赶读或尾音截断。发现问题如实标待复核/不合格，不用后配音或无限收费重做掩盖；这套模板是生成约束，不是质量或转化率保证。
- 字幕依据核实后的实际语音生成并对齐，不把预定脚本覆盖到不符的声音上。文字用本机`video_ocr`/`ocr`辅助复核；OCR不验口型。
- 真正核完才记录`voice_source:model_native`、`speech_reviewed/lip_sync_reviewed/appearance_reviewed:true`与成片SHA。工具不能提供可靠音画核验时标待复核，不能假装听过或强填true。
- 新收费重做先核授权范围，不以质量不佳为由无限重跑；发布、挂商品、音乐商用权限和AI标识分别核，不自动执行。

## 状态与恢复

| 状态 | 含义 | 你该做什么 |
|---|---|---|
| `queued` | 已登记，尚未提交 | 启动一次后台 run |
| `submitting` | 正在提交 | 等后台，不要重复启动 |
| `accepted` / `running` | 供应商处理中 | 等通知；用户问进度先给进度页链接 |
| `succeeded` + `file_status: ready` | 已下载完成，不代表内容合格 | 商品视频按实际比例/声音/口型/商品保真验收后交付 |
| `succeeded` + `download_failed` | 生成成功、下载失败 | 再运行一次同一 `run_command`，只重试下载 |
| `submission_unknown` | 提交结果无法确认 | **绝不重发**。让用户去供应商后台核对任务 ID；找到后调用 `video_attach_task`，再运行一次 |
| `failed` / `violation` | 明确失败或违规 | 读错误原因；修改提示词后重新准备新批次，不要原样重试 |
| `pending` | 本地等待超时，远端可能仍在跑 | 不重新提交；用更长 `--max-wait-min` 再运行一次同一批次 |
| `stopped` | 本地停止、丢锁或异常保护 | 远端不一定停止；先读`blocked_reason`或批次`note`。认证/额度/限流保护不会因重启解除，核对并解决后经用户授权再加`--resume-blocked`恢复同批，不重提failed/unknown项 |

`submission_unknown` 的处理最重要：没有供应商幂等接口，自动重发可能导致重复扣费。宁可让用户核对一次。

如果任务卡住且用户决定放弃，调用 `video_abandon_job`。明确告诉用户：这只释放本地名额，**不会取消远端任务**，如已提交仍可能计费。

## 交付格式

先给一句结论，再给表格：

| # | 状态 | 规格 | 本地文件 | 说明 |
|---|---|---|---|---|
| 1 | 完成 | 6s / 768p / 竖屏 | [product-hero.mp4](/absolute/path/product-hero.mp4) | — |
| 2 | 失败 | 6s / 768p / 竖屏 | — | 内容违规：…… |

然后补：

- 批次 ID；
- 成功数量 / 总数；
- 失败项的原因和下一步建议；
- 如果还有未完成项，给出**一条**恢复命令。

本地文件必须用绝对路径的 Markdown 链接。不要把 base64、API Key 或完整请求体贴到对话里。

## 不要做

- 不要用 curl、Python 或直接 HTTP 调用供应商接口；只通过本插件的 MCP 工具和 CLI。
- 不要把进度页链接、访问令牌或本机路径发到外部服务。
- 不要用进度百分比推断生成完成；只有 `succeeded` 且文件 `ready` 才算可交付。
- 不要在 `video_prepare_batch` 之后重复提交同一批次。
- 不要把提交超时当作失败后自动重试。
- 不要声称可以取消远端任务或退款。
- 不要把整段视频或 base64 放进模型上下文。
- 不要为了“确认状态”循环启动后台命令。
- 不要在提示词里写精确品牌文字、价格数字，除非用户接受后期处理。

## 常用示例

**一条产品视频**

> 用这张图做一条 6 秒竖屏产品视频，黑色石台，缓慢推进，轻雾，冷色高级感。

动作：`video_check` → 写提示词 → `video_prepare_batch`（`images` 传绝对路径）→ 一次后台 run → 交付。

**批量三个版本**

> 同一款香水做三个版本：白底展示、浴室生活场景、细节特写，各 6 秒，768p 竖屏。

动作：一个批次 3 条任务，共用一个 `client_request_id`，一次后台 run。3 条未超过 4 条，可直接执行。

**接着上次**

> 查一下刚才那批视频，失败的把下载补上。

动作：`video_list` 找批次 → `video_status` → 只对 `download_failed` 或 `pending` 的批次再运行一次，不重新准备、不重新提交。
