# 跨品类商品素材标准

用户确认于2026-11-07。适用于商品生成、重做商品素材、批量准备上架素材；不是只适用于某款卫衣。执行前先读本款事实及当前任务授权，沿用已有合格素材，只补缺项。维护规则、讨论方案、查进度不触发收费生成、公开图床或线上更新。

## 1. 每款交付

| 内容 | 默认要求 | 验收 |
|---|---|---|
| 商品展示图 | 8张，按款式/颜色安排 | 不是8张工厂原图或重复图；逐图与本款原图对照 |
| 尺码/尺寸规格图 | 1张，使用真实数据本地排版 | 单位、行列、测量口径与来源一致，OCR加视觉复核 |
| 商品视频 | 1条，服装口播约15秒、其他商品约10秒，严格9:16 | 模型原生人声、实际语音内容正确、人物口型匹配、商品保真 |
| 商品说明 | 西语客户正文大于500字符 | 不是500词；分段清晰，仅写有依据的特征 |
| 颜色图 | 每个本次在售颜色至少1张生成主图 | SKU颜色→本款该色主图的明确对应关系 |

- 8张是每款合计，不是默认每色8张。优先给每色分配主图，剩余位置安排背面、真实细节、场景等；不强求所有品类都用服装上身镜头。
- 人物适合商品受众，商品图可男女搭配；男装主图不因场景审美被误成女款。非服装可以人物持物/使用或产品展示，不能套衣服尺码/护理模板。
- 颜色超过8个时，补足额外颜色主图。相册精选8张展示图＋1张尺码图，额外颜色图仅用于对应SKU；不能漏色、挪用近似色、把多个独立文件拼成“已覆盖”。新增数量超过本次费用授权时先说明数量再生成。
- 没有服装尺码的品类，用真实的长宽高/容量等适用规格图；不存在的数据标缺失，不拿别款尺码或模型猜数代替。暂缺数据就交付部分结果并阻塞对应上架项。
- 工厂图是参考和事实证据，**不直接当新生成路线的商品图或SKU图上传**。已经在售的旧商品不追改；用户明确要求只用工厂图时才走例外路线。

## 2. 先锁款色，再一次编排整批

1. 从本款、同工厂证据锁定款号、实际在售颜色/尺码、单件或套组、材质与真实尺寸。面料GSM不是整件重量；不能把不明“280G”写成整件280g或自行补单位。
2. 建立显式颜色表：`平台颜色键(en) ↔ 西语展示名(es) ↔ 工厂该色参考 ↔ 生成主图文件`。键允许沿用既有SKU值（可能本身为西语），不假定en一定英语、不靠文件名模糊猜色。
3. 每个颜色参考不足时停止该颜色。白色图不能简单凭名称当黑色，花灰不等于纯灰；有印花时保持图案、位置、文字、比例，原本无印花不凭空加印花。**手机壳例外**：厂家只提供材质级实拍（每材质4–8张，常带示例印花），取其中一张最干净、外表面正对镜头、无印花的图作结构参考，按该材质在售颜色逐色改色生成；只改颜色，不改结构/孔位/镜头平台/机型。禁止把厂家多张示例图按顺序硬套成颜色图。
4. 一次准备全批提示词和稳定request_id，命名包含批次/款/颜色/镜头/版本，不能仅用跨批通用款号。参考图显式传入，不只写“和原图一样”。
5. 尺码数据本地排版，不让生图模型排数字。10款通常为80个AI图片任务＋10张本地尺码图＝90张交付图；多颜色补图另计。不要谎称向供应商发送了90个生图请求。

图片批量使用 `magpie-image` 技能中的 `scripts/batch-images.mjs`，完整清单一次预检、一次后台启动。默认整批并发提交，不采用“第一张完成→第二张提交”的串行方式。接口仍逐任务提交，插件批次入口负责一次编排；供应商排队与吞吐能力不保证90张同时渲染。遇401/403/429、额度或权限问题停止相关新提交、报告阻塞，不换通道绕过，不自动重发。

一个图任务一个独立提示词、`n=1`；不能用`n=4`冒充4个不同场景。依赖同一已核主图的后续任务可在必要依赖就绪后同批并行，不为无关款相互等待。用户明确要整批时，先用工厂原图统一准备可独立的任务，避免人为制造串行链。

## 3. 文件交付与图片验收

每款最终上传目录平铺，不按场景/颜色分子文件夹，例如：

```text
生成图/
  01-Blanco-正面.png
  02-Negro-正面.png
  03-Blanco-背面.png
  ...
  08-Negro-场景.png
  09-尺码表.png
  10-Azul-SKU主图.png  （仅有额外颜色时）
生成视频/
  01-商品介绍-9x16.mp4
商品描述-西语.md
```

任务原始下载放独立工作目录，与最终目录分离；不同任务不得都向同一目录写`01.png`。已有不同内容的文件报冲突，不静默覆盖。图片只有保存成功不算款式/颜色验收成功。

- 主体：款式、版型、颜色、图案、袋位/领口/抽绳/配件等对照工厂参考；生成特写不能成为未证实材质/走线的事实依据。
- 图片：当前TikTok主图JPEG/PNG、≤5MB、短边≥600px、比例3:4～4:3。保留母版，优先等比缩小/补边；不拉伸、不凭固定裁切参数切掉衣服/头顶/关键部件，也不AI补衣冒充原款。
- 尺码图：本款真实值、单位、对应颜色/尺码；不“平滑”原始数据跳变，不自行把平量翻倍。无已知量体口径就说明未知。
- 文案：按实际客户正文计数，移除内部管理标题、Markdown/HTML标记、链接目标，压缩连续空白后须>500字符。推荐600–900字符留余量，不靠空格、编号、网址凑数；不得为凑长度编造功效、材质、价格、运达、护理或统一选大一码建议。
- 不去除实物品牌充无标，不把AI生成图说成工厂实拍；按平台实际规则标注AI内容。

## 4. 视频原生声音与9:16

加载 `minimax-video` 技能执行。服装口播默认15秒并使用该技能的通用服装口播模板；其他商品包保留10秒。统一`aspect_ratio: "portrait"`（9:16）、768p；用户明确时长和已确认批次规格优先，不追改已登记或运行中任务。1080p最多10秒，规格冲突先确认；1080p和大批费用按该技能确认规则，不因本标准自动升清晰度或换模型。

- **由视频大模型直接生成自然西语人物声音和相应口型**。不运行macOS `say`、本地TTS或另造配音文件，不把本地配音塞入`audios`；商品包默认省略`audios`。用户另行提供参考音频是另一种明确需求，不能自行替换此默认。
- 技能先写定短而准确的对白与对应动作，再提交视频模型，不让视频模型自行编卖点。默认墨西哥西语，用户指定语言优先；15秒约25—32个西语词，10秒约18—22词，留自然停顿和完整尾音，不靠加速塞词。只讲真实特征和“查看商品尺码/规格”的引导；无已挂商品链接不谎称已经挂上。
- 开头直接展示产品并开口吸引注意；中间围绕一个真实特点边讲边展示；结尾自然引导。说话时嘴部清楚可见，不用画外旁白代替人物说话；特写放在停顿中。服装按上装/裤裙/连衣裙或套装调整构图，商品不被露脸或手势遮挡。禁止叠化分身、失真、乱加logo/字/花纹，不用图片轮播替代真实动作。
- `portrait`参数不证明实际文件9:16。用ffprobe检查显示尺寸、SAR=1:1、旋转方向，最终宽×16必须等于高×9。1056×1920不是严格9:16，也不能直接称1080×1920。必要时等比缩放补边，例如保持原幅不变补到1080×1920；保留母版，不拉伸或盲裁。
- 连续音画播放核实际说话内容、清晰度、逐音节嘴形和首尾，不只看几张张嘴截图。ASR只辅助；转写差异未排除就不能宣称脚本一致。音轨存在/音量曲线相关性不证明是有效口播或口型同步。
- 字幕从核实后的实际语音做，不把预定脚本强贴到不符的声音上。无法核实内容/口型就保留待复核状态，不标合格、不默认上传；质量失败需要新收费任务时先核授权，不无限自动重跑。
- 不默认添加版权不明音乐；生成/保存、内容验收、发布/挂商品分别记录。

## 5. 上架素材清单（当前可运行契约）

每个商品的现有spec保留`skuPrefix/description/images/colors/sizeChart`，新增`media`，不改原色码键。`images`为顺序固定的8张展示图＋第9张尺码图；`colors[].image`显式指向该色生成主图，允许额外颜色图不在相册中。

`media`结构如下（字段示意，assets必须包含全部实际使用的图片，不是可直接提交的完整商品spec）：

```json
{
  "mode": "generated",
  "assets": [
    {
      "product": "本款skuPrefix原值",
      "file": "/绝对路径/生成图/01-Blanco-正面.png",
      "url": "https://自有图床/已部署文件.png",
      "sha256": "实际文件的64位小写SHA256",
      "source": "generated",
      "source_ref": "真实生图task_id或可核对的生成回执",
      "role": "color_main",
      "color": "Blanco",
      "reviewed": true
    },
    {
      "product": "本款skuPrefix原值",
      "file": "/绝对路径/生成图/09-尺码表.png",
      "sha256": "实际文件的SHA256",
      "source": "local_chart",
      "source_ref": "/绝对路径/工厂尺码依据.json",
      "role": "size_chart",
      "reviewed": true
    }
  ],
  "video": {
    "file": "/绝对路径/生成视频/01-商品介绍-9x16.mp4",
    "sha256": "实际成片SHA256",
    "voice_source": "model_native",
    "speech_reviewed": true,
    "lip_sync_reviewed": true,
    "appearance_reviewed": true
  }
}
```

- `role`只取`color_main/product/size_chart`；非尺码图片`color`必须精确等于本款某个`colors[].en`。尺码图不填颜色。普通背面/场景图用`product`；每色至少一个`color_main`。
- `reviewed`等字段是实际完成检查后才记true，不由生成器/文件存在自动填true。SHA只绑定验收时的文件内容，不证明AI准确，也不能把虚构回执当来源证据。
- 托管前`images`、`colors[].image`、`sizeChart`填`{"file":"绝对路径"}`，不是本地路径字符串。托管后可以填HTTPS URL；assets保留本地文件和同一部署的url便于一致性检查。上架托管流程会回填这些URL。
- 同色各尺码共用该色主图；不同颜色不能共用同一主图。工厂图只能作`reference_images`/原始证据，不进入上述上传字段。没有该色图就阻塞该款，不默默回退首图。

本地无网络校验（不会开浏览器、部署或上传）：

```bash
node "$POD_REPO/tools/pod/listing/media-check.mjs" /absolute/current-spec.json
```

`publish.mjs`的plan/build/precheck/pagecheck/import在任何浏览器或图床动作前调用同一检查。缺清单、≤500字符、错色/跨款/工厂图、未核验、文件SHA变化、图数错误、非9:16、无音轨或视频未验收均阻塞。verify/deactivate的历史读取逻辑不受该素材门影响（下架本身仍需授权）。

用户明确选择工厂图直上时仅作例外：`media:{"mode":"factory_original","authorization":"用户真实确认及范围"}`。不能由代理为过检自动填此例外；它不等于生成素材合格。历史已上传表缺清单时保留原断点、不盲目重建，按本次真实授权核需要更新的素材；新上传和新导入不得借历史路径跳过检查。

## 6. 边界

素材规则跨品类复用，不表示上架类目、模板列位、店铺、库存、价格自动通用。新类目仍核真实官方模板；不改价、不追加颜色/尺码、不改线上图、不发布视频或挂商品，除非本次任务明确授权。批量生成只授权该批数量，不是永久允许无限再生成。只对新增或变化素材复验，复用有效证据。
