# POD / 成衣上架（原网页批量导入链）

目标是交付真实商品ID及核验结果，不是反复建资料包。适用店铺为 `tk-shop-a` / BRAND-A、墨西哥站；**不限定T恤**。裤子、水洗、Polo、卫衣、瑜伽等各取自己的官方类目与模板，不能只改类目名硬套T恤列位。与手机壳店铺 `tk-shop-b` 完全隔离。

## 先选最短路径

| 当前已有结果 | 下一步 |
|---|---|
| 真实商品ID／已点击导入但结果不明 | 去商品管理读回；不重新上传、不再点击导入 |
| 精确文件已在上传历史 | 就绪则核验后导入；失败则“立即更正”，只补真实缺项 |
| 已校验xlsx但未上传 | 使用该文件与本款官方模板依据；不为补spec而重建 |
| 只有商品证据／当前spec | 补必填事实、图床与本款模板，生成一次表再检查 |

成衣不需要透明生产图、印花冻结或银河设计。印花商品继续遵守其生产素材要求，但冻结不等于发布授权。用户说“同一流程”是沿用业务链，不自动创建动态Workflow；只有明确要求用workflow/工作流才启用对应工具。

首次遇到多品类模板、上传失败、读回异常或恢复任务时，按需读 [成衣导入与恢复参考](references/garment-import-recovery.md) 的对应段，不每款重读全文。

## 用户口径与授权：确认过的就落实

- 简体中文、结论先行、不称呼用户名字。先说明选用现有技能；进度只报实质变化，不逐按钮播报。
- 读取本款最新证据和用户真实确认，记录范围；旧文件里的“待确认”不推翻后来的人类确认。只有缺少关键事实、授权越界或不可逆动作才确认，并一次列全相关缺项。
- “每款50件”是**整款合计**，按本次真实有码的颜色尺码分配、合计校验；不是每色码50，也不是工厂盘点。用户授权额度可作上架数量依据，工厂实际库存未知仍保留unknown。
- 不存在／明确断货的尺码不上；整款断货不因表格残留编码恢复。颜色、量体和报价不能跨工厂混用。套组必须明确件数和组成，单件不冒充套装。
- 成衣重可在用户授权后当包裹重；面料GSM不是整件重。用户明确允许合理估算时，按单件折叠包装等明确假设填重量和三边，单独记为估算，不回写成工厂实测，不再重复追问同一数据。
- “不保修、不进口”这类明确口径，选平台实际的对应选项并读回。只适用于被确认的商品，不扩展到其他款、原产国、品牌或费用。
- “检查／分析”不授权发品；明确“导入／倒入／上架”后，在已展示或已授权范围内执行，不为相同范围重复审批。点击前仍核店铺、商品及数值；价格分析本身不授权改价。
- 用户排除RIIN／银河时整段跳过，不做同步、设计、映射、订单、推厂、付款。收费生图、对外发图或其他新外部动作另受授权约束。

## 输入与证据门

| 项 | 足够的依据 |
|---|---|
| 商品身份 | 款号、工厂、单件/套组、真实颜色尺码；实物品牌不明不声称无标，不去标充无品牌 |
| 发布数据 | 当前完整spec，或已验证xlsx及精确上传历史；不强制把已有成衣表迁移成T恤spec |
| 文案 | 西班牙语，标题≥25且<300字符；客户正文去内部标题/排版标记后>500字符，不是500词；同款各色码标题一致，无虚假功效/销量/产地 |
| 图片 | 新素材8张生成展示图＋1张本款尺码/尺寸图；每色生成主图与SKU精确对应。托管前spec可用`{file:绝对路径}`，上传表只能是有效HTTPS URL |
| 视频 | 1条，服装默认约15秒；本地时长检查为大于0且不超过20秒，实际9:16；模型原生人声、实际语音/口型/商品外观核验，不能只凭音轨存在或张嘴抽帧 |
| 售价 | 本款真实成本和当前费用模型；使用pod-pricing，条件余量不叫实收利润 |
| 数量 | 已确认供货/上架额度，已选色码数量之和等于整款额度 |
| 物流 | 显式重量(g)、长宽高(cm)，来自实测或用户明确允许的估算；禁止静默使用旧脚本200g/15cm缺省值 |
| 类目属性 | 当前官方模板的字段与允许值；缺项只补已知事实，不编值过检 |

上传表的材质等文本用官方西语选项；**网页标准下拉选项可显示中文**，选择其既有“无保修”“否”不等于把中文自由文本写入西语模板。不要凭翻译猜模板值。

图片要求：JPEG/JPG/PNG，单张≤5MB、最短边≥600px，主图比例3:4～4:3，单款最多9张。**照片不得有边框、白边或留白画布**；比例不符时按目标比例居中裁切（cover），不补白、不拉伸；原图单独保留。不AI补衣、不抹品牌、不把生成图称工厂实拍。需要读图中文字时复用本机 `ocr`，无文字不证明无品牌。

## 生成素材与SKU颜色门（所有品类）

加载`pod-pipeline`并按其`references/product-media-standard.md`准备素材清单。每款最终图片平铺；工厂图仅作参考，不直接填新商品的相册或SKU图。每个本次在售颜色至少一个已核验的生成主图，按`colors[].en`精确对应`colors[].image`；同色各尺码可复用，不能给所有颜色复制第一张。超过8色补颜色主图，相册仍精选8展示＋1尺码，其余主图供SKU。

手机壳另有一条：厂家只有材质级实拍（每材质 4–8 张，且常带示例印花），颜色图必须由**该材质的一张干净实拍改色生成**，只改颜色、不改结构/孔位/镜头平台。禁止把厂家多张示例图按行或按顺序硬套成颜色图；颜色名与生成图不符该色阻塞，不拿首图顶替。

- spec每款附`media.mode: generated`、`media.assets`（同款标识/绝对文件/实际SHA/来源回执/角色/颜色/验收）、`media.video`（实际文件SHA、model_native、语音/口型/外观验收）。字段完整例子见上述标准；不能虚填true过检。
- 先运行纯本地`node "$POD_REPO/tools/pod/listing/media-check.mjs" /absolute/spec.json`。它不访问店铺、不部署；`publish.mjs`的plan/build/precheck/pagecheck/import会在浏览器或图床操作前自动跑同一检查。verify历史读回不受影响。
- 检查图片数量、>500字符、每色主图、来源和哈希、视频实际9:16/音轨/时长及验收记录；它不自动识别实际颜色或评估口型，逐图视觉对照/连续音画检查仍必须做。
- 工厂图直上仅限用户明确例外：`media:{mode:"factory_original",authorization:"真实确认及范围"}`；不能为省事/过检自行添加。历史回执不改、新生成流程不借旧spec绕过。
- 已有xlsx/在线更正不盲目重建，但新上传/导入前也要核最终相册及逐色SKU图；如果当前表仍是工厂图或错色，先阻塞，不能依赖旧预检状态。
- 现有xlsx发布链不负责上传视频或挂商品。完整视频作为独立素材交付；平台视频入口另需明确授权，不能把本地合格说成已发布。

## 一次准备、逐款执行

1. **定位断点**：只读批次汇总、当前回执及相关款文件，建立简短状态表（店铺、款号、文件/SHA、阶段、缺项、已有ID）。复用未变证据，不重下模板、重部署图床或重查市场。
2. **复用通道**：先加载浏览器技能，按当前可用性操作。该店铺已验证的专用通道是 `tools/pod/listing/zhanfu-bridge.mjs`（PID绑定Apple Events）；普通Chrome/CDP不可用且本通道正常时，不来回试登录通道。核当前PID、窗口、完整标签列表与BRAND-A；不硬编码上次PID或标签索引。
3. **查重**：在商品管理“全部”按本款号／商品ID搜索。看到输入框值不算提交成功，核实际搜索条件和目标行／无匹配。已有ID就验收，重复/身份冲突先停该款。
4. **准备或恢复**：有上传历史就选精确文件。已有就绪数据不重传；只剩属性就在线更正。批量准备独立文件可并行，同一店铺同一页面的更正和最终发布串行，避免串款。
5. **一次完整核验**：确认文件、本款标题及商家SKU均匹配；核选中颜色尺码、每码价/数量、总量、类目、材质、相册和每色SKU图实际加载且颜色吻合、重量和三边。小改动对比前后，只复验受影响字段和发布关键数值。来源、配置或文件变了才失效重验。
6. **最终点击一次**：网页显示本款无错误/准备就绪且有真实发布授权时，先落简短导入意图，再点最终按钮一次。无回执先查历史/商品，不当作失败重发。
7. **真实读回**：读商品ID、状态、价格、色码数和总量；新商品详情逐码核商家SKU/价格/数量，逐色核生成主图及颜色（同色尺码共图不重复下载），并核物流与本次更正属性。只读，不点“更新”或“另存为草稿”。审核中如实报告；有限等待/刷新后仍审核中就交付待审状态，不无限等在售。
8. **收尾**：更新一处当前结果并让汇总/README指向它，旧失败回执不改成功。不为每个点击另写长文档。只关闭本次打开的临时详情/服务；按全局规则安全清理孤儿，保留用户浏览器和活跃工作进程。

网页交互以当前可见事实定位。一次观察可采集同一商品全部必要字段；一次状态改变后获取最小必要结果。不要每次点击都读整页/转储HTML，也不要无观察连续跨弹窗操作。标题、文件或控件不唯一时重新定位，不猜选择器或调用未证实API。

## 图床与命令：避免用旧默认覆盖已验证数据

基址读取 `$POD_REPO/.local/pod-image-base` 与本批实际有效URL，不以技能中的历史域名为准。`image-host.mjs`会读配置文件；`listing-step.mjs`另有旧默认域名，调用时用已有的 `POD_IMAGE_BASE_URL` 环境变量显式传本批基址，不擅改DNS/全局配置。探针用已知有效图片，不猜路径。部署前保留整个旧站点内容，防止旧商品图被删；本地SHA校验不冒充全部旧URL公网已验证。

既有封装：`<pod-image-listing>/scripts/listing-step.mjs`。`<pod-image-listing>`表示本次实际读取的插件根目录，不猜安装版本或仓库相对路径。

```bash
# 仅在环境变化/尚未验证时体检；PROBE为已知有效图片URL
POD_REPO=<项目根> POD_IMAGE_BASE_URL=<当前基址> POD_IMAGE_PROBE=<有效图片URL> \
  node <pod-image-listing>/scripts/listing-step.mjs doctor

# 仅适合当前builder已支持的模板、完整且最新spec
POD_IMAGE_BASE_URL=<当前基址> node <pod-image-listing>/scripts/listing-step.mjs check \
  --spec <当前spec.json> --prefix <款号> --out <新表.xlsx>

# 获得发布授权后使用；已有上传历史的成衣改走上述恢复路径
POD_IMAGE_BASE_URL=<当前基址> node <pod-image-listing>/scripts/listing-step.mjs publish \
  --spec <当前spec.json> --prefix <款号> --apply
```

- `check`不建商品，但会建本地表、可能部署公开图片并上传预检，**不是完全只读**；这些动作必须在本次授权内。
- 当前`publish.mjs`的`precheck/pagecheck/import`都会先`stageBuild`。旧spec缺物流/属性会覆盖后来修好的xlsx；所以**已有表/历史不是再跑旧publish命令的理由**。不要靠换名/空白变更绕同SHA保护。
- 45列运动模板不能假定旧43列builder兼容。既有成衣模板/回执有效就复用，必要改表用已装xlsx工具按真实字段最小修改，不顺手扩写发布器。
- `status --spec ... --title ...`依赖旧标题解析（仅Playera/Camiseta等），不是卫衣/Leggings查重和验收的唯一依据；以款号/真实ID在“全部”读回。
- `off --spec ... --product ... --apply`只用于明确授权的下架；本技能不自动下架其他商品。

## 常见结果的正确解释

- `12001038`同SHA重复：查精确历史，继续已有任务；不是改名重传。
- `12052588 This page is outdated`：停止直连publish，回网页正常按钮；不伪造签名绕过。
- `pre_check code 0`：只代表该接口接受，不证明图片、属性或发布成功。
- 泛化“网络/20MB”横幅：先看本文件在线编辑器的具体错误；不未经证据就换网络、重建或重传。
- 列表暂时没有、无成功横幅：可能异步/过滤/懒加载，先正确搜索再有限等待；已点过不重复点。
- 详情编辑页提示尺码表/保修政策：如实记为资料缺项，不推翻已读回的在售事实；不造尺寸或文件消提示。
- 401/403/429、验证码、权限或额度限制：停止相关动作，报告真实阻塞，不绕限制。

## 交付与维护

交付表先列商品、真实状态、售价（MXN及按明示汇率折人民币）、色码数、总量和ID；列未完成项与未操作边界。证据至少包含来源文件/SHA、授权、点击及读回时间、逐码结果；UTC和本机日期跨日要标明。不把“已保存/准备就绪/已点击”说成“已上架”，不把本地记录说成远程备份。

不导出Cookie/Token、签名附件URL或工厂私链；认证留站斧。维护本技能先备份、检查源码与安装副本，只同步本次文档；不要整包覆盖已有代码漂移。新规则替换冲突旧文，不层层追加互相矛盾的门槛。
