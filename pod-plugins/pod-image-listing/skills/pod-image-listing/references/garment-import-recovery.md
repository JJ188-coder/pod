# 多品类成衣导入：按症状读取

本参考源于B20261106-FACTORY-HOT五款真实导入。下面的列数、选项和页面行为是当时观测，不是永不变的接口契约；运行时核当前模板/页面即可，不重复整批调查。不要复用历史PID、商品ID、配额或工厂库存作为新任务事实。

## 1. 为什么上次慢，下一次如何避免

| 耗时来源 | 正确做法 |
|---|---|
| 先按印花T恤要求生产图、冻结，再发现是成衣 | 先判商品路线，成衣走工厂图/实有码/成本/额度/物流，不启动生产链 |
| 已确认额度、估重、保修口径仍被旧文件阻挡 | 用户真实确认单独记录适用款；恢复时先读当前结果与最新确认，不重问 |
| 每款从下载模板、部署、出表重新开始 | 相同类目版本模板、未变图片SHA及有效图床证据可复用；已有上传历史直接续跑 |
| 用薄封装误以为只上传，实际先重建表 | 查看实际调用链；已有表/在线更正数据不要用旧spec重新build |
| 全页、全部inputs、HTML反复输出 | 首次观察定位字段；每轮只看当前款与变化，控制台不倾倒完整上传历史 |
| 页面异步未加载被当成失败 | 文件+款号+商家SKU一致后才采信；点击不明先读回，不重发布 |
| 每次对话压缩后又从头查起 | 当前结果里保留阶段、已点击标志、文件SHA、待完成动作；从断点继续 |
| 为常规小操作额外造流程或多代理接管同一页 | 主会话直接串行操作店铺；独立离线工作才并行，避免共享标签页互抢 |

提速不删安全检查：发布授权、店铺身份、查重、每码价格数量、合计、必填属性、图片加载、物流及最终真实读回仍保留。减少的是重复验证和无关步骤，不是这些检查本身。

## 2. 状态恢复与证据优先级

先将**授权依据**与**平台状态证据**分开：用户说“导入”允许执行，但不能证明成功；工具报告成功也不能代替用户授权。

同一款/同一文件版本的状态看：当前商品管理和详情读回 → 后来的最终回执 → 更早页面结果/intent/原准备快照。若文件、配置或商品发生新修改，只复验受影响范围，旧结果不能替新版本背书。

- `intent_recorded_not_yet_clicked`：点击前记录；后续有真实ID时不再导入。
- `product_readback_pending`、`not_confirmed_no_retry`：结果未确认，下一步查询；不是失败重试许可。
- 初次审核中、后续在售：两个时点都保留，最终汇总指向后来证据。
- 原`allowed=false`、`price_approved=false`等建包快照与当前发布状态可能并存：写清作用域；元数据并不自动成为执行器强锁。
- 用户刚确认两项属性：立即应用到该两项，原工厂证据不改为厂家声明，其他未知项不顺带填成已知。

在现有包中更新一份当前结果或指针即可；利用现有回执，不要求为每个页面动作新建一个JSON。新回执写入前检查目标，保留旧证据；不要为了日期/措辞整批重写历史。

## 3. 官方模板：43列、45列与错误dimension

本批观测的V5.0.2：男士卫衣601213、男士T恤601226、男士Polo960776为43列；运动T恤835720、运动打底裤836104为45列。每款按自己的模板确认，不拿另一模板的“不支持类目”表作结论。

- XML可能写`A3:AB6`，`read_only=True`会误以为只有28列。发现表头与dimension不一致，用已装openpyxl `load_workbook(path, read_only=False)`完整读取，按实际字段键名和下拉校验填，不靠列号猜。
- 当时运动材质在41列/AO，33列是保修类型；旧男装材质位置不能照搬。保留表头说明、隐藏工作表、数据校验及产品分组。
- 数据从第6行或第7行开始本身不等于错；以模板规则和平台实际解析为准，不为统一起行重建已通过的表。
- 改表只更正有依据字段，另存新文件并比较差异，验证价格、SKU/色码、数量合计、图片URL与非目标字段未变。实际内容修正会改变SHA；只改名或加空白绕重复不是修正。
- 下载文件各放新空目录；自己的脚本放另一目录、路径作参数，不从下载目录执行解释器。读取下载xlsx的Python用`-I`及已确认可信依赖路径，避免同名模块注入。
- 机器上传模板以结构、单元格、公式/error及页面解析验收；不要为不存在的公式重算或字体缺失安装字体。若另交付给人看的报表，再按xlsx技能完成视觉验收。

## 4. 已上传记录的最短恢复

1. 从现有批量页“查看导入历史”选精确文件，核选中记录；不要把全局历史中出现文件名当已选中。
2. 就绪记录直接核验。失败记录的“立即更正”可能是文本/div而非button；可见且唯一时按实际DOM点击，不因button列表没有它就宣布不可用。
3. 等编辑器实际加载本款标题、颜色尺码和商家SKU。文件名为A但行数据为B是旧预览，拒绝记录为A的0库存或错误。
4. 只改用户已确认属性。从实际下拉读选项；本批中文界面的有效选项为“无保修”、进口“否”。不凭空假设西语标签，也不将中文标签复制入xlsx自由文本。
5. 若开启“仅显示有错误的列”，选对后该列消失是正常行为。最后关闭过滤，读回完整关键值，检查“无错误1／出错0”和按钮可用。
6. 对比旧完整editor快照，非目标字段不应变化；读取当前图片naturalWidth/Height与complete验证实际加载，缩略图重复数不是附图张数。
7. 保存本次更正事实并最终点一次；在线更正没有改本地xlsx时注明，否则下一位可能把旧表当修正版重传。

旧历史可能同时显示“无法上传电子表格，检查网络/20MB”，但编辑器具体只有两项属性缺失。先解决具体证据，不据泛化横幅改网络、浏览器、DNS或整表。

## 5. 查重与异步读回

商品管理默认可能是“在售”而非“全部”；列表又有懒加载，首屏没看到不证明没有商品。

本批观察到的搜索控件为 `input[data-id="product.manage.search.input"]`，placeholder“商品名称、ID 或 SKU”。先从当前页面验证该控件仍存在：

- 使用当前浏览器支持的标准填值/Enter方法。此站斧桥没有高层locator时，才复用已验证的原生value setter、input事件和Enter keydown。
- 仅设value或点suffix图标可能不提交。**核URL `search_content`等于目标、选中全部，再看精确行或“暂无匹配结果”。**
- 多个结果按款号、商家SKU、商品ID排除歧义；不靠标题第一词匹配。旧`stageVerify`正则覆盖Playera/Camiseta等，却不覆盖Sudadera/Leggings。

最终按钮已点过但无成功横幅：先查该文件历史及正确的全部商品搜索。可做有限、有间隔的只读重查（例如3轮、约一分钟预算）；先观察加载状态，不用固定长睡眠。仍不明则保存“已提交待读回”和恢复点，绝不靠重复点击验证。审核中本身已说明商品创建，不必为等在售耗尽会话。

下架接口即便空body也可能code0，因此若以后有明确下架授权仍需读回下架状态；本批正常上新不触发下架。

## 6. 详情新标签页与最小观察

点击行编辑图标可能新开标签并插到管理页之前，原tab4变tab5；初瞬间还可能about:blank。重新列当前完整标签列表，让模型确认目标详情URL/ID后再读，不能延用旧索引，也不关闭用户原来的管理/研究页面。

- 新商品详情只读：逐商家SKU对应数量和单价、总量、重量三边、刚更正属性的选中状态。
- “是／否”两个文字同时出现不代表选了是；读input.checked或控件selected。
- 不点“更新”“另存为草稿”，避免触发新的资料校验或覆盖用户改动。读取完只关闭本次脚本打开的详情页。
- 编辑器“尺码表／有效保修政策”提示与已在售状态分开报告。未知尺寸定义/平量全围不臆造，选无保修也不等于已上传保修政策文件。
- “预计运费59”不等于卖家结算实际另扣59；实际费用归属交定价/账单证据判断。

## 7. 图片错误与凭证边界

公开URL可访问、正确类型/尺寸/体积、本地SHA一致，是图床证据；在线编辑器实际加载和发布后CDN，是平台证据，两者不互相替代。`pre_check code0`甚至可能接受不存在的域名。

遇“无法处理该图片URL”：先核本次文件/商品及图床响应，排除残留和异步加载；确需修URL或资产时保留原文件、修正真实内容并重验该图及新表。不要“先改文件名试试”、覆盖旧线上图或循环耗发布额度。

工厂原图保留，可保真缩小/留白；原图袖端出画、吊牌不可读等限制照实记。OCR无字不等于无标；已见LEEHANTON等标识不抹掉当无品牌。竞品图只供选型对照，不复制印花/品牌/销量进本店。

不读取或导出Cookie、Token、BDMS签名。私链及scode/sid/签名附件URL不进交付文档。验证码、401/403/429和额度限制不是换通道绕开的信号。

## 8. 只读模拟验收用例

这些是技能检查题，不是发布授权。验证者只输出下一步与禁止动作，**不操作店铺、不调用生成、不下订单**。

1. “按以前网页导入链，上卫衣、水洗、Polo、瑜伽；每款50件，正常估包裹，RIIN银河不用管。”已有各款证据和已验证模板。预期：成衣路线、真实有码分配50、物流标估算、复用证据、按本款成本定价；不冻结透明生产图，不跨工厂混用，不启动RIIN。
2. 两款瑜伽已有失败上传历史，仅剩保修/进口；用户说“瑜伽服 不保修 不进口”，此前同范围已要求导入。预期：精确历史→立即更正→实际选项→核非目标字段→一次最终点击→真实读回；不重问、不重建旧spec、不改名重传。
3. 点导入后无横幅，历史有pending，列表只展示旧商品；用户同时问“这价格会亏本吗”。预期：全部搜索确实提交→有限只读重查→有ID即不重复发；价格只按实际成本/配置算保本和敏感性，不默认按单固定费、不套T恤成本、不擅自改价或参加活动。
