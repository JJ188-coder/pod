# 故障排查（都是真踩过的）

按现象查。每条都写了**怎么判断**和**怎么修**。

---

## 1. `APPLE_EVENT_12` / `-2700`：页面 JS 关着

**现象**：桥接一执行页面脚本就报「通过 AppleScript 执行 JavaScript 的功能已关闭」。

**判断**：换个只有属性读取的操作（列标签页）能成功，执行 JS 就失败 → 是开关问题，不是标签页问题。

**修**：站斧菜单 **查看 → 开发者 → 允许 Apple 事件中的 JavaScript** 打开。
**这不是脚本能改的设置**，必须人工开一次。

---

## 2. `ZHANFU_TAB_INDEX_REQUIRED` / 对错店铺

**现象**：找不到批量页；或读到的窗口名不是 `tk-shop-a`。

**原因**：站斧同时开了多个实例（我们这机器上曾有 `tk-shop-c` 和 `tk-shop-a` 两个）。

**判断**：

```bash
ps -Ao pid,comm | grep zhanfu | grep -v Helper
```

主程序路径是 `.../Contents/MacOS/zhanfubrowser`，其余是 Helper（不可脚本化）。
再看每个 PID 的窗口名，只有 `tk-shop-a` 能操作。

**修**：所有命令都加 `--pid <正确的PID>`，不要依赖自动发现。

---

## 3. `修复 N 件出错的商品`（每波都失败，N 还不一样）

**现象**：第一波可能报真错，后面每一波都秒失败，报同一个 N。

**原因**：页面**残留**上一份表的错误横幅。表已经换过了，横幅还在。

**修**：每波导入前先重载批量页（`goto-batch.mjs`），等页面加载完再预检。
我们第一轮 10 波全被这个假错误挡掉，加这一步后 10 波一次过。

---

## 4. `product_count` 小于款数（多款并成一个商品）

**现象**：发 3 款，`product_count: 1`、`sku_count: 12`。

**原因**：**标题完全相同**，平台按标题合并成一个商品的多 SKU。

**修**：标题逐款唯一（我们用 `…Modelo {款号}` 收尾）。改完重新建表，`product_count` 必须等于款数。

---

## 5. `IMAGE_VERIFY_FAILED` / `UNREACHABLE`

**现象**：`--stage build` 或 `precheck` 报图片不可达。

**原因 A**：spec 里是本地文件 `{file:...}`，但用了 `--host static`。static 模式不改写 URL，等于空链接。

**修**：要么用 `--host pages` 走托管，要么先 `--stage plan` 托管完，再用 `--base-url` 生成 URL 版 spec。

**原因 B**：图床有瞬时抖动（实测偶发 403）。

**修**：`curl` 逐张验一遍；`urllib` 会被 UA 限流，用 `curl -A "Mozilla/5.0"`。

---

## 6. 部署卡住：`operation was aborted due to timeout`

**现象**：文件多时 `wrangler pages deploy` 超时。

**修**：分两步——先只跑 `--stage plan`（托管 + 逐张验证），确认 URL 全部 200 后，
后续 precheck / import 一律用 URL 版 spec + `--host static`，不再重复部署。

---

## 7. 主图被拒：比例超限

**现象**：plan 阶段某张图 ok=false，原因写 aspect。

**规则**：主图 **3:4 ~ 4:3**、最短边 ≥600、JPEG/PNG、≤5MB。

**实例**：六色汇总图做过 964×700（1.377）直接超 4:3，重做成 1080×1080 才过。

**修**：出图时就把尺寸锁在 1086×1448（0.75）或 1080×1080（1.0），不要事后裁。

---

## 8. 建表报 `Cannot convert {'file': ...} to Excel`

**原因**：尺码表没被托管，openpyxl 收到的是 dict 而不是 URL。

**修**：`publish.mjs` 的 `stagePlan` 里必须把 `sizeChart` 一起排队托管（本包已修）。

---

## 9. 详情图保存后消失

**现象**：往商品编辑页的富文本里插图，页面上看得到，保存后没了；连纯文本也丢。

**原因**：编辑器是 ProseMirror，保存读的是内部文档模型，不是 DOM。脚本注入无效。

**结论**：**这条路别做了**。要么人工拖拽，要么原生 GUI 输入。自动段不包含详情图。

---

## 10. 扣图出现黑方块

**现象**：把图案贴到黑衣服上，出现一块深色矩形。

**原因**：银河生产图的深色底是**不透明**的，直接按 alpha 贴就会留方块。

**修**：`compose-refit.py` 默认 `dark_bg=True`，按亮度重建透明度
（`alpha = art_alpha × lift(lum)`），深底被抠掉，暗部设计元素保留。

---

## 11. 印位贴歪（背图跑到男模手臂上）

**原因**：底图面板坐标标错（把女装背面的 x 区间量窄了）。

**修**：每张底图的面板框单独标定并存成 `bases.json`；
贴完**必须肉眼验一次**，因为自动检测会被深色阴影/牛仔裤干扰（我们试过连通域和 1-D 扫描，都不可靠）。

---

## 12. 报「不允许辅助访问」/ `WINDOW_ERR`

**原因**：给 Terminal/ZCode 的 macOS 辅助功能权限没开，System Events UI 自动化不可用。

**修**：这条不影响主流程（主流程走 Apple Events 执行页面 JS，不走 UI 自动化）。
真要做 UI 点击，去「系统设置 → 隐私与安全性 → 辅助功能」授权。
