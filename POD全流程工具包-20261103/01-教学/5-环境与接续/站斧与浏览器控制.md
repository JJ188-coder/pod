# 站斧与浏览器控制

本文是迁移到新 mac 后的控制边界和现场操作说明。它不安装站斧，不重启浏览器，不改登录、Profile 或出口，也不把旧电脑的 PID、Cookie、token、代理凭据带到新电脑。

下面用 `REPO` 表示交付仓库根，`PROJECT` 默认表示 `REPO/project`。控制脚本在：

```text
$PROJECT/work/zhanfu-instance-control-20261022/native-control/appleevents-control.js
```

## 1. 当前真实链路

旧电脑上已验证的是**原版站斧 5.2.9 的按 PID Apple Events 页面 JavaScript**，不是标准 CDP，也不是恢复版 CDP 桥。历史证据记录了页面 JS、图片上传、标题草稿保存和管理页回读；这只能证明旧电脑那个实例的那条链路，不能直接复制成新电脑的通过结论。

| 层次 | 已有证据 | 不能据此声称 |
|---|---|---|
| 原生 Apple Events | 按指定 PID 读取窗口名、当前标签 URL；执行页面 JS 的保护脚本 | 新电脑上的站斧实例已可用 |
| 页面写入 | 旧实例曾上传图片、填写标题、保存草稿并回读 | 新电脑已登录、已保存或已发布 |
| 恢复版 CDP 桥 | 离线桥接测试 8/8；源码和测试可查 | 原版 5.2.9 已开放标准 CDP |
| 端口 12621 | 曾观察到握手 | 它是标准 CDP，或属于哪个店铺实例 |

恢复版 `kingmaozi/zhanfu` 的固定提交和桥测试是开发证据，不是新电脑上的安装证明。不要把恢复版桥、原版 Apple Events 和普通 Chrome CDP 混成“已经接通”。

## 2. 新电脑的登录、Profile 和固定出口

由本人在新电脑按厂商正常迁移/登录路径恢复站斧和店铺。每店保留原来的固定出口安排；如果需要迁移 Profile，只采用厂商提供的正常迁移方式，不手工复制 Cookie、Local Storage、密码库或未知二进制 Profile。

`setup-macos.sh` 和 `doctor.py` 都不会：

- 安装或启动站斧；
- 改系统代理、店铺代理或登录；
- 导出或输出 Cookie/token；
- 读取或校验出口 IP；
- 自动打开店铺或执行页面动作。

新电脑的出口是否与店铺绑定，必须另看网络侧证据。一个浏览器能打开 `seller-mx.tiktok.com`，不等于它属于正确店铺，也不等于出口正确。

## 3. 每次动作前重新发现 PID

脚本始终读取窗口 1，并要求窗口名等于期望店铺。不要从旧记录复制 PID，也不要用同名 App、bundle ID 或最近打开的窗口猜店铺。先用只读命令发现候选 PID，再逐个核对窗口名和 URL。

```bash
REPO="${REPO:?set to the delivery repository root}"
PROJECT="${PROJECT:-$REPO/project}"
CONTROL="$PROJECT/work/zhanfu-instance-control-20261022/native-control/appleevents-control.js"

# 只列 PID 和进程路径，不打印完整启动参数，避免把代理/账号参数带到终端。
for pid in $(pgrep -f '站斧' 2>/dev/null || true); do
  ps -p "$pid" -o pid=,comm=
done
```

从当前输出中选定一个 PID，替换下面示例的变量；**不要把示例 PID 写成新机配置**。

```bash
# 示例：EXPECTED_SHOP='tk-shop-b'。两者都必须来自本次现场，不使用旧 PID。
EXPECTED_SHOP="${EXPECTED_SHOP:?set to the current window name}"
BROWSER_PID="${BROWSER_PID:?set to the current PID}"

osascript -l JavaScript "$CONTROL" "$BROWSER_PID" "$EXPECTED_SHOP" inspect
```

`inspect` 只读窗口 1 的名称和当前标签 URL。通过条件必须同时满足：

1. 窗口名与 `EXPECTED_SHOP` 完全一致；
2. 目标是已存在的、允许操作的 `https://seller-mx.tiktok.com` 页面；
3. PID 是本次现场发现的值。

脚本遇到 `SHOP_MISMATCH` 会立即抛出并停止。不要换成另一个同名进程重试，不要用 CUA 菜单去猜实例，也不要修改窗口顺序来“让它通过”。重新核对当前实例和店铺，再从头执行。

查看已存在标签：

```bash
osascript -l JavaScript "$CONTROL" "$BROWSER_PID" "$EXPECTED_SHOP" tabs
```

如果目标 `seller-mx` 标签不是当前激活标签，可从输出取得它的序号，显式传给 `eval`。脚本对显式标签同样做 origin 检查；`SELLER_ORIGIN_MISMATCH` 是停止条件，不要改成别的域名，也不要为了通过检查而新开页面。

## 4. 只读检查和页面探针

现有 `page-probe.js` 只返回标题、origin、path 和 readyState，不读取 Cookie、storage、账号调试文本或整页隐藏内容：

```bash
PAGE_PROBE="$PROJECT/work/zhanfu-instance-control-20261022/native-control/page-probe.js"
osascript -l JavaScript "$CONTROL" "$BROWSER_PID" "$EXPECTED_SHOP" eval "$PAGE_PROBE"
```

如需指定已有标签序号（序号来自上面的 `tabs` 输出）：

```bash
osascript -l JavaScript "$CONTROL" "$BROWSER_PID" "$EXPECTED_SHOP" eval "$PAGE_PROBE" 2
```

`eval` 只接受 `https://seller-mx.tiktok.com` 的同源页面；表达式文件必须是当地已存在、经过审阅的脚本。不要把任意 `document.body.innerText`、整页 HTML、登录态或隐藏账号调试值作为探针输出。

页面 JavaScript 还需要在**当前这个实例**的浏览器菜单里由本人启用“允许 Apple 事件中的 JavaScript”。脚本无法代替这个开关；未授权时可能得到 `APPLE_EVENT_12`、权限拒绝或进程级错误。出现这些错误时停下，核对实例和权限，不循环重试。

## 5. 手机壳与 T恤必须分开

下面是项目当前记录，不是新电脑上的现场证明。新电脑恢复后仍需重新核对 PID、窗口、店铺和域名。

| 业务 | 当前店铺记录 | 历史草稿/控制对象 | 硬边界 |
|---|---|---|---|
| 手机壳 | `tk-shop-b` / BRAND-B | 草稿 `2000000000000000004` | 手机壳工厂 500000/650000、手机壳规则；不套用银河 T恤尺寸 |
| T恤 | `tk-shop-a` | 草稿 `2000000000000000005` | RIIN/银河、`MXTMC001`、36×56cm 与 S≈80% 规则；不套用手机壳规则 |

不要在一个店铺窗口中用另一个店铺的 PID、草稿 ID 或商品 ID。即使窗口标题相似、App bundle ID 相同，也必须以当前窗口名和 URL 为准。

## 6. 写入、保存和回读纪律

- 先预览目标字段，再填写；不把旧草稿的字段默认值复制到新商品。
- 图片使用实际 `input[type=file]` 的 `change` 流程；图库满后 input 位置会变化，不能盲用固定索引。
- 普通文本/数字先聚焦、选择、插入并触发正常事件，再失焦；只改 DOM `value` 不等于保存成功。
- 描述编辑器可能是懒加载的 ProseMirror；先滚入视口，等待挂载，再用正常粘贴流程，完成后失焦。
- 保存后等待“草稿保存成功”和按钮加载结束，再打开新 document 重开回读；异步上传期间立即读取可能看到旧快照。
- “已保存草稿”“已重新读回”“已提交审核”“已发布”“已生产”是五个不同状态，不互相替代。
- 没有明确业务授权时，不提交审核、不发布、不付款、不推厂、不删除重要数据。

历史旧实例上的现场 PID（例如 57188）只作追溯，不是新机默认值。图片上传成功也不能证明工厂图库已匹配、SKU 库存已确认或最终成本已核对。

## 7. RIIN 与 EchoTik：同源、只读、有预算

交付基线统一使用 Node 24：RIIN 现有说明的最低要求是 Node 22，EchoTik 素材 SDK 要求 Node 24 或更高。RIIN 通过既有登录页面和同源客户端；EchoTik 默认走公开模式，CDP 模式只复用既有公开页。两者都不把 Cookie 或 token 取回 Node。

### RIIN

入口：

```text
$PROJECT/output/mx-riin-sdk-20261022/sdk/riin-readonly.mjs
```

使用规则：

- 只复用已打开的 `https://tshirt.riin.com` 页面；不新开标签、不自动登录、不重启浏览器。
- 默认单实例最多 8 次主动业务请求，最小间隔 500ms；这是 SDK 操作预算，不是平台额度。
- 只允许已列出的读取查询；不因为接口是 `GET` 或名字叫 `list` 就执行未知接口。
- 认证失败、验证码、限流、连接关闭时停止；不自动重连、不自动重试、不自动轮询。
- 已有共享连接时先检查 socket 状态；旧实例曾经 ready 不代表现在在线。

### EchoTik 素材 SDK

入口：

```text
$PROJECT/output/mx-first-product-20261022/周榜20款图片包-20261012-20261018/sdk-assets/bin/echotik-assets.js
```

使用规则：

- Node 24 或更高，零第三方依赖；`--help` 和 `--dry-run` 都不访问网络。
- 单批最多 20 个商品，公开 HTML 请求和 CDP 连续读取至少间隔 1 秒。
- 公开模式走正常公开请求；CDP 模式只复用已有 `echotik.live` 正常页，不新建页面、不导航、不刷新，target 不存在就直接失败。
- 401、403、429 或验证码出现后停止该入口，不自动重试；剩余条目记录为 skipped。
- 连接关闭（例如旧会话的 1006）后不自动重连，不把已保存数据当成当前在线。

doctor 只检查这些文件是否存在、RIIN 脚本是否带请求预算标记；它不运行活体请求，也不检查在线 socket。

## 8. 当前新机验收顺序

1. 先运行 `scripts/setup-macos.sh` 和 `scripts/doctor.py`，只确认工具和文件条件。
2. 本人在厂商正常路径恢复站斧和店铺登录，不导出 Cookie。
3. 对每个店铺重新发现 PID，执行 `inspect`，通过窗口名和 origin 检查后才做 `tabs`/只读探针。
4. 需要写草稿时，从已确认的既有草稿开始；保存后重开回读，不重复创建新草稿。
5. 需要 RIIN/EchoTik 数据时，先检查现有页面/连接，再按 SDK 预算做一次小请求；失败即停。
6. 记录新机实际证据；旧机 PID、旧登录和旧聊天记录都不能作为新机通过证明。
